# Narration image remediation evaluation

**Recommendation: BLOCKED.** Do not deploy the narration image routinely. No residual risk is accepted. Do not treat the separate `--ignore-unfixed` pass or the lower Trivy count as proof of fixes.

Assessment date: 2026-11-10. Source baseline: `179a71312f93279f6fab4b65dc08143c02eb952d`. Environment: Windows host, Linux Docker Engine 29.9.3; Trivy 0.76.2 with vulnerability DB updated 2026-11-10 19:01 UTC. No model was downloaded, no Wan inference was run, no service was deployed, and no CI policy or risk-acceptance decision was changed.

## What changed in scanner results—and what did not

Candidate 2 has 24 fewer unique CVE IDs in Trivy than the refreshed baseline (74 to 50). Seventeen FFmpeg CVEs disappear from the package scan because the candidate statically compiles FFmpeg 7.1.5, which Trivy does not identify as a Debian package. Seven more disappear because candidate 2 no longer contains `libxi6` and `libcjson1`:

- `libxi6`: CVE-2026-109089, CVE-2026-109090.
- `libcjson1`: CVE-2026-16554, CVE-2026-29036, CVE-2026-67215, CVE-2026-67216, CVE-2026-87933.

Those are package/module removals, not patched findings. The backported libcurl binary now contains upstream fixes for CVE-2026-12064 and CVE-2026-8458, but Trivy still reports both as `affected` with no fixed version; neither is counted as scanner-cleared. Candidate 2's 136 H/C records include 134 with Trivy status `affected`, one `fix_deferred`, and one `will_not_fix`; no H/C finding reports a fixed version. The package risk register covers 50 Trivy CVEs plus 17 separately assessed static-FFmpeg CVEs (67 unique CVEs across 16 source/build groups); repeated binary-package findings remain in the detailed inventory. The complete per-CVE package, function/precondition, module, and reachability notes for the 17 static FFmpeg findings are in [candidate2_static_ffmpeg_assessment.csv](./candidate2_static_ffmpeg_assessment.csv).

Candidate 2 now installs Debian's supported Trixie-backports `libcurl4t64 8.21.0-2~bpo13+1` from the `curl` source package. Debian's CVE trackers identify fixes for CVE-2026-12064 and CVE-2026-8458 in upstream 8.21.0; the backport changelog identifies it as a Trixie-backports rebuild. The strict scan nevertheless retains both as `affected` with no `FixedVersion`, so scanner counts remain unchanged and neither CVE is counted as Trivy-cleared. The backport updates `libnghttp3-9` to `1.15.0-1~bpo13+1` and adds `libngtcp2-16` and `libngtcp2-crypto-ossl0` at `1.22.1-1~bpo13+1`; all three were included in the package diff and strict scan, with no H/C finding on those dependency packages. Sources: [Debian backports package](https://packages.debian.org/trixie-backports/libcurl4t64), [Debian backport changelog](https://metadata.ftp-master.debian.org/changelogs//main/c/curl/curl_8.21.0-2~bpo13+1_changelog), [CVE-2026-12064 tracker](https://security-tracker.debian.org/tracker/CVE-2026-12064), and [CVE-2026-8458 tracker](https://security-tracker.debian.org/tracker/CVE-2026-8458).

Candidate 2's FFmpeg recipe [Dockerfile.minimal-ffmpeg](../../../../services/narration/Dockerfile.minimal-ffmpeg) pins Debian builder/runtime base digests, the Debian snapshot, FFmpeg 7.1.5 archive SHA-256, and x264 commit. It removes FDK-AAC and `--enable-nonfree`, uses FFmpeg's native AAC encoder, compiles FFmpeg statically, and configures `--disable-network` with only `file` and `pipe` protocols. Runtime enumeration confirmed those protocols only. The specifically reviewed vulnerable FFmpeg components for 16 CVEs are not compiled:

`CVE-2026-58049`, `64830`, `64832`, `64833`, `64834`, `64835`, `66036`, `66039`, `66040`, `66041`, `70628`, `70632`, `75142`, `75143`, `75144`, and `75146` (all prefixed `CVE-2026-`).

This is component-level attack-surface reduction, not a software fix; shared-code safety is not established. `CVE-2026-75141` remains potentially reachable because HEVC demux/decode and MP4 muxing are enabled. PNG/APNG encoders and the `quirc` filter are absent; the enabled image output uses MJPEG. Further FFmpeg changes require repeating module and compatibility checks.

## Priority package assessment

The official source-package tracker pages linked below were checked directly. Their displayed suite matrix includes Trixie, Forky, and Sid; the cited tracker rows do not show a Trixie fixed version for the prioritized findings. This is separate from the verified `curl` Trixie-backports package above, which contains upstream fixes despite Trivy's unresolved status. A missing backports row is not evidence that no backport could later be published. Per-CVE Debian status links are also present in the finding inventory.

- **Tesseract 5.5.0-1+b1:** Debian lists Trixie 5.5.0-1 as vulnerable for candidate findings CVE-2026-73066, CVE-2026-88047, CVE-2026-88048, CVE-2026-88051, CVE-2026-88052, and CVE-2026-88053; Sid 5.5.4-1 is fixed for these listed CVEs. The upstream advisory for CVE-2026-73066 fixes the crafted-model heap overflow in 5.5.3; the newer candidate findings are fixed in the Debian Sid 5.5.4-1 tracker entry. No Trixie fixed package/backport appears in the checked tracker matrix. The vulnerable condition for CVE-2026-73066 is untrusted `.traineddata`. Fixed executable/tessdata paths, explicit `eng`, a SHA-256 allowlist, removal of `TESSDATA_PREFIX`, and fail-closed asset checks block that model-injection route. They do **not** patch Tesseract or clear the image/parser findings, which remain potentially reachable through extracted frames. Sources: [Debian Tesseract tracker](https://security-tracker.debian.org/tracker/source-package/tesseract), [upstream CVE-2026-73066 advisory](https://github.com/tesseract-ocr/tesseract/security/advisories/GHSA-7j76-5rq5-5jg8).
- **libxml2 2.12.7+dfsg+really2.9.14-2.1+deb13u3:** Debian lists Trixie as vulnerable for CVE-2026-6653, CVE-2026-74860, CVE-2026-86138, CVE-2026-86139, CVE-2026-86140, CVE-2026-86142, CVE-2026-86143, and CVE-2026-86144; 2.15.4+dfsg-1 in Forky/Sid is fixed for the latter group, while CVE-2026-74860 has an upstream fix in 2.15.3. No Trixie fixed package/backport appears in the checked tracker matrix. The candidate has no `python3-libxml2` package and no importable `libxml2`/`lxml` Python module; application search found no direct libxml2 or Python SAX use. This narrows CVE-2026-74860's Python SAX path, not the C library or other findings. Trivy marks CVE-2026-6653 CRITICAL using NVD severity (NVD CVSS 9.8); Debian's tracker marks Trixie vulnerable `<no DSA>`. Sources: [Debian libxml2 tracker](https://security-tracker.debian.org/tracker/source-package/libxml2), [upstream CVE-2026-74860 fix](https://gitlab.gnome.org/GNOME/libxml2/-/commit/f41e1865781f74d1cadfe2fbdfeefed946026f12).
- **FFmpeg:** Debian Trixie 7:7.1.5-0+deb13u1 remains vulnerable for the assessed source-package CVEs; the Debian tracker marks many as postponed, while Forky/Sid 9.0.2-4 fixes several. For CVE-2026-58049, Debian's tracker identifies the upstream `decode_dlta` RASC decoder flaw and points to a fix in upstream 9.x; candidate 2 excludes the RASC decoder but does not patch FFmpeg shared code. Candidate 2 also leaves CVE-2026-75141 potentially reachable through enabled HEVC demux/decode and MP4 muxing. No supported Trixie backport was identified in the checked tracker matrix. Sources: [Debian FFmpeg tracker](https://security-tracker.debian.org/tracker/source-package/ffmpeg), [upstream CVE-2026-58049 fix](https://code.ffmpeg.org/FFmpeg/FFmpeg/commit/11ff18a6c80187405fc492f9bb07ba9f2f663f76).
- **util-linux 2.41.5-0+deb13u1:** Trixie is vulnerable with `<no DSA>` status for CVE-2026-76642, CVE-2026-78408, CVE-2026-78409, and CVE-2026-78410; Forky/Sid 2.42.4-1 are fixed. The upstream advisory lists CVE-2026-76642 fixes in 2.41.6/2.42.3 and describes the failed-mount-helper/post-hook precondition. The application does not invoke mount/nsenter operations; worker UID 10001, dropped capabilities, and no-new-privileges reduce relevant privileged-operation preconditions but do not patch the package. Sources: [Debian util-linux tracker](https://security-tracker.debian.org/tracker/source-package/util-linux), [upstream CVE-2026-76642 advisory](https://github.com/util-linux/util-linux/security/advisories/GHSA-m25x-3hj9-m26f).
- **curl/libcurl 8.21.0-2~bpo13+1:** candidate 2 now installs Debian's supported Trixie-backports package, which contains upstream fixes for CVE-2026-12064 and CVE-2026-8458. Debian's Trixie tracker assessments are minor/no-DSA; Trivy 0.76.2 still reports both as `affected` with no fixed version, and they remain visible and unresolved in the scanner inventory. `/usr/bin/tesseract` links `libcurl.so.4` and `libtesseract5` depends on the package; the curl CLI is absent from the candidate image, and application code does not invoke a libcurl API directly. The updated package-level decision and reassessment conditions are in [candidate2_backport_risk_register.csv](./candidate2_backport_risk_register.csv).

It does not show a fixed package version for this set. There is no direct Kerberos API call in the application, but individual native callers and exploit preconditions remain unverified. Source: [Debian krb5 tracker](https://security-tracker.debian.org/tracker/source-package/krb5).
- **Other H/C source packages:** all remaining findings, source/binary package mappings, installed versions, Trivy status, dependency rationale, controls, residual decision, and reassessment triggers are in the risk register. `libtiff` includes a `will_not_fix` finding and `perl` a `fix_deferred` finding. Upstream patch status not established for a package/CVE is explicitly left unresolved rather than inferred from a missing Debian fixed version.

## Runtime compatibility and isolation

Candidate 2 passed FFprobe H.264/AAC probing, FFmpeg mux/render, a real faster-whisper CPU-int8 transcription using the pre-existing local model (`This is a synthetic narration security test.`), English Tesseract OCR (`SYNTHETIC SECURITY`), eSpeak synthesis, source video/audio stream preservation, and source-byte preservation. The rebuilt candidate image digest was `sha256:22d176c320c73c7b4c31c1b4cca8072b042f6ef763117986f411bb4beb1f9062`; the synthetic fixture SHA-256 was `be2bff9ff635a82e8349a1f8ed0d3f21c0df05074678b21c11290bf59a359f54`. The model volume and source fixture were mounted read-only; the model write probe was denied. [Rebuilt-image smoke results](./candidate2_smoke_results_backport.json) record exact image digests, output hashes, and inspected constraints.

The candidate smoke used `--network none`, `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges:true`, CPU 2, memory 2 GiB with swap equal to memory, PID limit 128, a 512 MiB `noexec,nosuid` tmpfs, UID/GID 10001, and a read-only model volume. No DB credentials or Docker socket were passed/mounted. Its fixture generator also ran network-disabled with a read-only root, all capabilities dropped, no-new-privileges, CPU 1, memory 512 MiB, and PID limit 32. These test controls are not production isolation: the inspected live worker still has private control/inference network access and DB/Redis credential environment entries. Candidate 2 was not deployed, and no dedicated short-lived parser container was implemented. Routine deployment should remain blocked until supported fixes or an owner-approved, verified parser boundary removes those credentials/network paths and residual risks are reviewed.

The reproducible command is recorded above and the harness is checked into `scripts\smoke_narration_candidate.ps1` plus `scripts\smoke_narration_runtime.py`. A previously denied combined Git status/reference and Docker image/volume-listing action was not retried. The full original request arguments were not retained, so the exact denied argument list cannot be disclosed.
